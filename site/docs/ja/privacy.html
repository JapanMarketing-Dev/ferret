データとプライバシー

レビューはプロジェクトのフォルダに、設定は ~/.ferret/ に、キーとアカウントは OS のユーザーデータのフォルダに置かれます。開発者に届くのは Sentry 経由のクラッシュレポートだけで、これは止められます。アプリから自分で送ったフィードバックは、公開の GitHub の issue になります。YouTube や TikTok に投稿する動画は、「OK・投稿する」を押したときだけ、自分の PC からそのサービスへ送られます。最終更新日: 2026年10月18日。

#.ferret/reviews/ の中身

<project>/.ferret/reviews/20261003-104500/
├── feedback.md      # what the agent reads
├── 01.png, 02.png…  # one or more images per finding
├── session.json     # review state and edit history
├── events.jsonl     # action log (built-in browser only)
├── recording.webm   # the video
└── work/            # intermediate audio and frames

名前を変える前に作ったレビューは .ade-movie/reviews/ にあります。これも一覧に出て開けます。新しいレビューは .ferret/reviews/ に入ります。

録画を始めると、.git/info/exclude に .ferret/ を書き足します。worktree と submodule にも対応しています。.gitignore は書き換えません。途中で止まったレビューは、記録が残っていれば履歴から復元できます。そのときは、最後の数秒が欠けているかもしれないと警告が出ます。

#保管期間

録画の保管（最初の設定は7日。30日か ずっと も選べます）: 起動したとき、その期間より古い完了済みのレビューから recording.webm と work/ を消します。feedback.md と指摘の画像は残ります。完了していないレビューは消しません。消す処理は起動時に、最後に開いたプロジェクトに対して行います。

#アプリからのフィードバック

GitHub のアカウントが無くても、Ferret の中から不具合の報告や案を送れます（サイドバーの下の フィードバックを送る）。送るのは自分で送ったときだけで、JapanMarketing-Dev/ferret （新しいタブで開きます） に from-app のラベル付きで公開の issue として載ります。人前に出したくないことは書かないでください。

  • アプリは自分のパソコンから小さな中継（開発者が動かす Cloudflare Worker）へ送り、中継が自分の GitHub のトークンで issue を作ります。自分で作った共有リンクを除けば、書いた内容を受け取る開発者のサーバーは、この中継だけです。
  • 送るもの: 題名と本文、不具合か案か、アプリのバージョン、添えた PNG か JPEG のスクリーンショット3枚まで。OS の名前とバージョン、CPU のアーキテクチャ、ランダムなインストール ID は、含めたままにしたときだけ送ります。送らないもの: 名前、メールアドレス、GitHub のアカウント、プロジェクトのファイル、録画、指摘。
  • issue を作る前に、中継はキーやトークンに見える文字、メールアドレス、ホームフォルダのパスの中のユーザー名を伏せ、@mentions で誰かに通知が飛ばないようにします。スクリーンショットからは位置情報などのメタデータも取り除きます。それでも伏せきれないことがあるので、文は自分でも確かめてください。
  • 中継は IP アドレスを保存しません。1人が投稿できる回数（1時間に5回、1日に20回）を抑えるため、IP アドレス（と、送っていればインストール ID）の鍵付きハッシュを最長24時間数え、その後に消します。どちらも issue には出ません。
  • スクリーンショットは、中継が推測できない名前で Cloudflare R2 に置き、issue に表示します。issue やそのスクリーンショットを消してほしいときは、その issue にコメントするか、新しい issue を作ってください。
  • 中継のコードはリポジトリの workers/feedback-relay にあります。

#YouTube（YouTube API サービス）

Ferret は、YouTube API サービスを使って、あなた自身の YouTube チャンネルに動画をアップロードします。アップロードするのは、Ferret で Google アカウントを連携し、動画の「OK・投稿する」を押したあとだけです。連携することで、YouTube 利用規約 （新しいタブで開きます）に拘束されることに同意したものとみなされます。Google によるデータの取り扱いは Google プライバシー ポリシー （新しいタブで開きます）に書かれています。

  • 求める権限: 動画をアップロードするための youtube.upload と、動画のサムネイルを設定し、連携したチャンネルの名前を読み取るための youtube.force-ssl。
  • 使うデータと使い道: 承認した動画・サムネイル・メタデータ（タイトル、説明、タグ、公開設定など）をチャンネルにアップロードし、終わったかどうかを表示するためにアップロードの状況を読み取ります。チャンネルの名前は、どのチャンネルを連携しているかを表示するためだけに読み取ります。Google アカウントのほかのデータを読み取る・集める・共有することはなく、広告や分析にも使いません。
  • 送り先: 自分の PC から Google へ直接送られます。Google アカウント、チャンネル、投稿した動画のどの情報も、開発元やほかの誰かに送られることはありません。クラッシュレポートにも、トークン・動画・タイトル・チャンネル名は入りません。
  • 保存場所: OAuth のトークンは自分の PC の中にだけ、OS のキーチェーン（macOS のキーチェーン、Windows の DPAPI、Linux のシークレットサービス）で暗号化して、Ferret の userData フォルダに保存します。連携したチャンネルの名前も、アプリに表示するためにその隣に保存します。動画と投稿の設定はプロジェクトのフォルダに残ります。
  • やめ方: Ferret の設定から、いつでも Google アカウントの連携を解除できます。解除すると PC からトークンを削除します。Google のセキュリティ設定 （新しいタブで開きます）から Ferret のアクセス権を取り消すこともできます。すでにアップロードした動画は、YouTube で削除するまで YouTube に残ります。
  • Google API から受け取った情報の Ferret による利用と移転は、制限付き使用（Limited Use）の要件を含め、Google API サービスのユーザーデータに関するポリシー （新しいタブで開きます）に従います。

#TikTok

TikTok を連携した場合、Ferret は TikTok の Login Kit と Content Posting API を、あなたが承認した動画とキャプションを「OK」を押したあとにあなたの TikTok アカウントへ投稿するためだけに使います。TikTok の利用には TikTok 利用規約 （新しいタブで開きます）とプライバシーポリシー （新しいタブで開きます）が適用されます。

  • 求める権限: 連携したアカウントの表示名を表示するための user.info.basic と、動画を TikTok の受信箱に送るための video.upload（投稿の仕上げは TikTok アプリで行います）。直接投稿する video.publish は、TikTok が Ferret に許可したあとにだけ求めます。
  • 送り先と保存場所: 動画とキャプションは自分の PC から TikTok へ直接送られます。トークンは YouTube と同じく、自分の PC の中にだけ OS のキーチェーンで暗号化して保存します。Ferret の設定で TikTok の連携を解除すると削除します。TikTok アプリの設定から Ferret のアクセス権を外すこともできます。
  • トークンの中継: TikTok では、サインインのコードをトークンに換えるのにアプリのクライアントシークレットが要り、そのシークレットはアプリの中に入れられません。そこでこの手順だけ、Ferret は開発元が動かす小さな Cloudflare Worker（https://ferretade.dev/oauth/tiktok/）へリクエストを送ります。受け付けるのは3種類（サインインのコードの交換、トークンの更新、トークンの取り消し）だけで、クライアントシークレットを付けて TikTok へ転送し、TikTok の答えをそのまま PC へ返します。コード、トークン、IP アドレス、アカウントについての情報は記録も保存もせず、動画やキャプションを受け取ることもありません。

#クラッシュレポート

アプリが落ちたり、処理されないエラーが起きたりすると、Ferret は不具合を直せるよう Sentry （新しいタブで開きます） にクラッシュレポートを送ります。最初の設定ではオンです。設定 → プライバシー → クラッシュレポートを送る か、初回の起動で出るお知らせの OFF にする で止められます。止めるとすぐに効きます。もう一度オンにしたときは、次の起動から効きます。開発用のビルド（pnpm dev）も development の札を付けて送るので、開発者は作業中に出会ったクラッシュも直せます。E2E の実行と単体テストからは送りません。

送るもの送らないもの
  • エラーの種類とメッセージ（ホームフォルダのパスは ~ にします）
  • スタックトレース（Ferret のコードのどこで起きたか）
  • ネイティブのクラッシュでは、どのプロセスが落ちたか、なぜ終わったか（たとえば crashed や oom）、アプリのバージョン、クラッシュの種類と落ちたモジュールのファイル名、そして場所: そのモジュールの中の位置、落ちたスレッドのスタックにあったモジュールの位置（20 件まで）、そのモジュールのデバッグシンボルを引くための ID、スレッドの名前。その起動での Ferret 自身の直前の手順（30 件まで。終了や更新のインストールなど）も送ります。メモリの中身・アドレスそのもの・ファイルのパスは送りません
  • OS の名前とバージョン、CPU のアーキテクチャ、Electron / Chrome / Node のバージョン、アプリのバージョン、画面の大きさ、メモリの量
  • エラーの直前のアプリの節目の出来事（たとえば app.ready）と、起動の失敗
  • アプリのどこで失敗したか: 描けなかった画面の部分（とその React のコンポーネント名）、IPC の呼び出し、起動できなかったターミナル、落ちたか固まったプロセス、読み込めなかったアプリのページ
  • アプリのどこにいたか: エディタモードかフィードバックモードか、開いていたタブ（ブラウザ、指摘、設定、またはただの file）、録画中だったか
  • 起動ごとに1つのセッション（始まった、ふつうに終わった、落ちた）。バージョンごとにクラッシュしなかった割合を測るためです
  • ランダムなインストール ID（初回の起動で作り、アプリの設定フォルダに置きます）。影響を受けたインストールの数を数えるためです。名前、メールアドレス、端末とは結び付きません
  • JavaScript のクラッシュのときだけ: Ferret 自身のログの最後の50行（[startup] や [recording] など）。短くし、パス、URL、メールアドレス、キーを取り除きます
  • プロジェクトのフォルダのパスとファイル名（<project> に置き換えます）
  • 内蔵ブラウザで開いた URL と、その他の Web アドレス（<url> に置き換えます）
  • ターミナルの出力、文字起こし、指摘、ページの文字、スクリーンショット
  • メールアドレスと API キーやトークン（置き換えます）
  • 名前、端末名、IP アドレス（保存しません）、Cookie、ローカル変数
  • ネイティブのクラッシュのメモリダンプ（minidump）。メモリにあったものが何でも入りうるので、自分のパソコンに残します
  • クリック、ネットワークの要求、Ferret 自身のものでないログの行

インストールしたアプリが送るのは起動ごとに最大10件で、JavaScript のエラーは半分だけ送ります（ネイティブのクラッシュは必ず送ります）。開発用のビルドはすべてのエラーを、起動ごとに50件まで送ります。同じエラーは起動ごとに1回だけ送ります。遅い起動（5秒を超えるもの）と、アプリが長く固まったとき（1秒を超えるもの）は警告として、10分に1回まで送ります。パフォーマンスのトレースとセッションリプレイは使いません。アプリは Sentry の無料プランを使っています。上限に達したら余った分は捨てられ、誰にも料金はかかりません。

Ferret を自分でビルドする場合は、FERRET_SENTRY_DSN（古い名前の MOVIE_ADE_SENTRY_DSN も使えます）に自分の Sentry の DSN を入れるか、空の文字列にして何も送らないようにします。コードは src/main/telemetry.ts と src/shared/telemetry.ts にあります。
