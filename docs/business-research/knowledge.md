# 集客の5原則：マーケティング理論から実践方法まで（ユーザー提供ナレッジ 2026-10-18）

## 結論
集客とは、広告や営業によって人を集めることではなく、「特定の顧客が抱える問題に対して、適切な価値を、適切な場所とタイミングで届け、利益を生む顧客関係を構築すること」。コトラーのマーケティング論と整合する。
AIで開発・調査・広告制作・営業準備のコストが下がっているため、次の順で運用する:
市場調査 → 顧客選定 → 課題の特定 → 価値提案 → 集客経路の検証 → 販売 → 継続改善
商品を作ってから集客するのではなく、集客と購入が成立する条件を先に発見してから商品を作る。

理論的な基盤:
| 理論・提唱者 | 中核となる考え方 | 今回の用途 |
|---|---|---|
| フィリップ・コトラー | STP、4P、顧客価値 | 市場と顧客の選定 |
| セオドア・レビット | マーケティング近視眼 | 商品ではなく顧客の欲求から考える |
| クレイトン・クリステンセンら | Jobs to Be Done | 顧客が解決したい仕事を特定 |
| マイケル・ポーター | 競争戦略、差別化 | 競合に対する優位性の設計 |
| バイロン・シャープ | メンタル・フィジカルアベイラビリティ | 顧客に想起され、購入可能な状態を作る |
| ピーター・フェーダーら | 顧客価値・顧客中心の経営 | 顧客単位の収益性を考える |
| エリック・リース | Lean Startup | 小さな実験で仮説を検証する |

5原則: 1. Who 誰に売るか / 2. What 何を解決するか / 3. Where どこで顧客を獲得するか / 4. Why なぜ競合ではなく自社を選ぶか / 5. How どうやって再現性のある利益にするか。
各原則を「理論 → インターネット調査 → 判定方法 → 実験方法」の順に整理する。

## 第1原則：Who — 誰に売るか
### 理論：コトラーのSTP
- Segmentation（市場細分化）: 市場を共通の特徴を持つ顧客集団に分ける。
- Targeting（標的市場の選定）: 優先して獲得する顧客集団を選ぶ。
- Positioning: 選んだ顧客の頭の中で自社がどんな価値を持つ存在になるかを設計する。
最初に「できるだけ多くの人」を対象にしない。例:「日本企業向けの営業支援ツール」は広すぎる。「従業員20〜100人のIT企業で、新規法人営業を担当し、営業先リスト作成に毎週5時間以上使っている責任者」なら具体的に顧客を探せる。

顧客を分ける5つの軸:
| 分類軸 | 確認する内容 |
|---|---|
| 属性 | 業種、企業規模、所在地 |
| 状況 | 採用拡大中、営業強化中、事業立ち上げ中 |
| 行動 | 特定ソフトの利用、求人、広告出稿 |
| 課題 | 時間不足、コスト増、売上機会の損失 |
| 購買条件 | 予算、決裁者、導入時期、既存契約 |
B2Bでは企業属性だけでなく企業が現在置かれている状況が重要（新規事業を立ち上げた企業と既存事業を維持している企業では買うものが違う）。

### インターネット調査
企業公式サイト、採用情報、プレスリリース、有価証券報告書、求人媒体、既存サービスの導入事例。AIで構造化する項目: 企業 / 業種 / 従業員数 / 状況（例: 法人営業を3名募集中）/ 推定課題 / 課題の証拠（求人URL）/ 購買担当候補（営業部長）/ 到達経路（公式問い合わせ窓口）。
求人から営業拡大の可能性は推測できても、営業リスト作成に困っているとは断定できない。観測した事実と推測した課題を分けて保存する。

### 判定方法（市場全体の大きさより重視）
- 対象企業を具体的に特定できる
- 同じ課題を持つ企業が一定数存在する
- 購入担当者を特定できる
- 支払い能力がある
- 同じ方法で繰り返し接触できる
対象企業が数千社しかなくても、単価と利益率が十分なら魅力的な市場になり得る。

### 実験方法
特定セグメントを100社程度抽出し個別にアプローチ。返信率だけでなく、対象企業数 → 担当者到達率 → 商談率 → 課題一致率 → 購入意思 を測る。

完了条件: 顧客企業のリストを作成でき、その企業が購入する可能性を説明できる。

## 第2原則：What — 何を解決するか
### 理論：レビットとJobs to Be Done
マーケティング近視眼＝自社商品に注目しすぎて顧客が本当に求める価値を見失う。顧客が欲しいのは営業リストそのものではなく、商談や売上を増やすこと。
JTBD 例: 表面的なニーズ「営業リストを作りたい」→ 実際の仕事「新規営業の担当者が、今週アプローチする企業を見つけたい」→ 深い目的「限られた営業人員で商談数を増やしたい」。ここまで分解すると、営業先の優先順位付け・担当部署の特定・営業タイミングの通知などが価値になる可能性がある。

### 需要の強さの5要素
| 項目 | 評価する内容 |
|---|---|
| 深刻度 | 解決しないとどの程度困るか |
| 頻度 | どのくらい繰り返し発生するか |
| 経済的損失 | 金銭・時間・機会損失の大きさ |
| 緊急性 | いつまでに解決する必要があるか |
| 既存支出 | すでに解決のためにお金を使っているか |
頻度が低くても一度の損失が大きければ魅力的（毎日のデータ入力 vs 年1回の重要な法令対応）。単純な合計点ではなく課題の種類も区別する。

### 証拠の強弱
| 証拠 | 何を示すか | 信頼性 |
|---|---|---|
| 実際の契約・発注 | お金が使われている | 高い |
| 既存製品の有料利用 | 市場に支払意思がある | 高い |
| 予算付きの募集・入札 | 購入する具体的な意思 | 高い |
| 競合の導入事例 | 課題解決への支出実績 | 比較的高い |
| 製品レビューの不満 | 改善余地 | 中程度 |
| 検索需要 | 情報探索の存在 | 中程度 |
| SNSでの不満 | 課題の存在可能性 | 低〜中程度 |
| AIによる課題推測 | 調査すべき仮説 | 低い |
既存支出と不満が同時に確認できる市場を重視。ただし不満があっても乗り換えコストが高ければ参入は難しい。

### 課題の定量化
例: 営業リスト作成に月40時間 × 人件費4,000円/時 = 月16万円。80%削減なら理論上12.8万円。ただし削減時間の金銭換算であり、現金支出が減るとは限らない。課題を金銭・時間・売上機会に変換する。

完了条件: 誰が、どの状況で、何に困り、現在いくら負担していて、解決すると何が改善するのかを証拠付きで説明できる。

## 第3原則：Where — どこで顧客を獲得するか
### 理論：4Pとバイロン・シャープ
| 4P | 意味 | 集客への関係 |
|---|---|---|
| Product | 製品・サービス | 顧客が求める価値 |
| Price | 価格 | 購入の経済的障壁 |
| Place | 流通・販売経路 | 顧客が購入できる場所 |
| Promotion | 販売促進 | 認知・検討してもらう方法 |
集客は Promotion だけではない（普段使うツールに組み込まれていれば広告なしで接点が生まれる）。
シャープ: Mental Availability（購入を考える場面で思い出しやすい）/ Physical Availability（見つけて購入しやすい）。知名度ではなく、購入場面で想起され実際に購入できることが重要。
応用例（入札情報サービス）: 「入札案件を探したい」と思ったときに検索結果に出る＝想起・発見の接点。検索結果から案件詳細を確認でき、そのまま無料登録できれば障壁が下がる。顧客が課題を感じた瞬間に自社サービスへ到達できる状態を設計する。

### 集客経路を選ぶ原則
| 顧客の状態 | 適した経路 | 具体例 |
|---|---|---|
| 解決策を検索している | SEO・検索広告 | 「営業リスト 作成ツール」 |
| 既存製品を比較している | 比較ページ・レビュー | 「〇〇 代替」 |
| 課題はあるが探していない | 直接営業 | 特定企業への提案 |
| 同業者から情報収集する | 紹介・コミュニティ | 業界団体・専門家 |
| 業務中に課題が発生する | 無料ツール・連携 | 無料の企業検索 |
| 定期的に情報を確認する | 通知・メール | 新着入札案件の配信 |
顧客が集まっている場所と購入意思が生まれる場所は異なる（SNSに経営者が多くても法人保険をその場で買うとは限らない。更新時期が近い企業へ提案が届けば少ない接触でも商談になり得る）。

### 調査方法
検索経路: Google検索結果、キーワードプランナー、Search Console、自社の検索データ。項目: 検索キーワード / 検索ボリューム / 検索意図（情報収集か購入検討か）/ 競合ページ / 広告出稿 / 検索結果の構造（新規サイトが参入できそうか）。検索ボリュームだけで判断しない（少なくても購入意図が明確で高単価なB2Bキーワードは価値がある）。
直接営業経路: 公式サイト・求人・プレスリリース・事業報告から購入可能性の高い企業を抽出。無差別に集めず、購入のきっかけとなる出来事（トリガー）を検出する: 営業担当者の大量採用 / 新事業部の設立 / 新拠点の開設 / 特定業務の外部委託の募集 / 既存システムの更新予定。購入を保証しないが営業対象を絞る有力な仮説。

### 集客経路の評価5軸
| 評価軸 | 判断基準 |
|---|---|
| 到達可能性 | 顧客へ接触できるか |
| 購入意図 | 接触時点で課題を認識しているか |
| 獲得コスト | 1顧客獲得にいくらかかるか |
| 再現性 | 同じ方法で継続的に獲得できるか |
| 拡張性 | 投資を増やして獲得数を増やせるか |

完了条件: 顧客がどこにいて、どのタイミングで、どの経路から接触すればよいかを説明でき、小規模な集客実験を実施できる。

## 第4原則：Why — なぜ自社が選ばれるか
### 理論：ポーターの競争戦略
競争優位は主にコスト優位と差別化。AIによる開発・運用コスト削減は優位にできる可能性があるが、AIで安く作れること自体は長期的な差別化にならない（競合もAIを使える）。既存サービスを安く再現するだけでは価格競争に陥る。低コスト構造を使って顧客にとって意味のある違いを作る。

### 乗り換える理由
乗り換えにはデータ移行・教育・業務変更・セキュリティ審査のコストがある。
概念式: 新サービスの期待価値 − 導入負担 − 乗り換えリスク ＞ 現状維持の価値
例: 月10万円 → 月3万円の代替で年84万円安くなるが、移行に100万円かかり運用リスクも高ければすぐには乗り換えない。既存サービスと併用でき導入作業がほぼ不要なら採用されやすい。

### 差別化の種類
| 差別化 | 具体例 | 注意点 |
|---|---|---|
| 価格 | 競合より大幅に安い | 模倣されやすい |
| 性能 | 精度・速度が高い | 客観的な検証が必要 |
| 利便性 | 導入・操作が簡単 | UXの継続改善が必要 |
| 専門性 | 特定業界に最適化 | 対象市場が狭くなる |
| データ | 独自の情報を保有 | 収集・更新コストが必要 |
| 流通 | 顧客が自然に見つけられる | 集客基盤の構築が必要 |
| 信頼 | 品質保証・実績・認証 | 獲得に時間がかかる |
特に「価格」「データ」「流通」の組み合わせに注目。無料の企業情報DBは無料だけなら追随されるが、継続収集データ・利用者の検索条件・独自の更新検知・関連サービス連携が積み上がれば模倣しにくい。ただしデータ量だけでは優位にならない（正確性、独自性、利用権限、更新頻度、顧客の利用価値が必要）。

### 調査方法（機能一覧だけを比較しない。購入を決める条件を調べる）
| 調査対象 | 確認内容 |
|---|---|
| 高評価レビュー | 顧客が最も評価している価値 |
| 低評価レビュー | 不満・未解決課題 |
| 解約に関する投稿 | 離脱理由 |
| 競合比較記事 | 購入時の比較基準 |
| 料金体系 | 価格と提供価値の関係 |
| 導入事例 | 採用理由・導入効果 |
問い: 顧客が既存サービスをやめる、あるいは新たに自社サービスを追加する明確な理由は何か。ここが曖昧なら開発するべきではない。

完了条件: 特定の顧客が自社サービスを選ぶ理由を一文で説明でき、その理由が顧客の実際の評価や行動によって裏付けられている。

## 第5原則：How — どうやって利益を生む集客を再現するか
### 理論：顧客生涯価値とユニットエコノミクス
CAC = 顧客獲得に要した費用 ÷ 新規有料顧客数（例: 広告20万＋営業10万で10社 → 3万円。人件費・制作費などの含め方を統一）。
LTV ≈ 月額売上 × 限界利益率 × 平均継続月数（例: 月3万 × 80% × 24か月 = 57.6万円）。新規事業では継続期間が未確定なので、複数の継続期間を仮定して感度分析する。

### ファネルの分解（B2B直接営業）
| 段階 | 指標 |
|---|---|
| 対象企業抽出 | 条件に合う企業数 |
| 接触 | 接触できた企業数 |
| 反応 | 返信・問い合わせ率 |
| 商談 | 商談化率 |
| 提案 | 提案率 |
| 契約 | 成約率 |
| 継続 | 継続率 |
| 拡大 | アップセル・紹介率 |
例: 1,000社 → 反応50 → 商談20 → 契約5 で対象からの契約率0.5%。件数を増やすのではなく、どの段階がボトルネックかを特定する。反応率が低い→ターゲットか訴求。商談率が高いのに成約率が低い→価格・機能・信頼・導入負担。

### AIによる改善サイクル
データ収集（広告・検索・問い合わせ・商談・利用状況）→ 原因分析（獲得率・成約率・継続率の変化）→ 改善仮説（ターゲット・訴求・価格・機能・導線）→ 実験（LP・広告文面・オンボーディングの変更）→ 評価（売上・限界利益・CACへの影響）。
AIが改善案を出しただけでは効果があったとは言えない。A/Bテストや段階的展開などの比較が必要。初期は有意差が出ないこともあるので、定量データとヒアリングを組み合わせて判断する。

完了条件: 新規顧客の獲得から継続利用までの主要指標を測定でき、利益を維持しながら顧客獲得を増やせる見通しがある。

## 5原則を統合した事業探索プロセス
| 段階 | 原則 | リサーチで確認すること | 実験で確認すること |
|---|---|---|---|
| 1 | Who | 対象顧客・企業数・購買担当 | 実際に接触できるか |
| 2 | What | 課題・既存支出・不満 | 本当に解決を求めているか |
| 3 | Where | 検索需要・営業経路・競合の流通 | 低コストで顧客を獲得できるか |
| 4 | Why | 競合の弱点・価格・乗り換え障壁 | 自社を選ぶか |
| 5 | How | 市場規模・価格・コスト構造 | 利益と継続率が成立するか |
5原則は独立していない（ターゲットを変えれば課題も経路も変わる）。一度決めて終わりではなく、市場実験の結果で繰り返し修正する。

## インターネットリサーチで実現する具体的な仕組み：6つの機能を持つ市場探索システム
（ユーザー原文が途中で切れたため、前後から推測して補った。2026-10-18 にユーザーの確認を経て、この6機能を正とする）

| 機能 | 原則 | 何をするか |
|---|---|---|
| 1. 顧客・企業の発見 | Who | 公式サイト・求人・プレスリリース・有価証券報告書・導入事例から企業を構造化して集める。項目は、企業・業種・規模・状況・推定課題・課題の証拠URL・購買担当候補・到達経路。セグメントの5軸（属性・状況・行動・課題・購買条件）でリストを作る。 |
| 2. 需要・支出・不満の証拠収集 | What | 契約・発注・入札・料金・レビュー・掲示板・SNS・解約理由を集める。原文・URL・確認日・事実・推論を分けて保存する。証拠には8段階の強さ（証拠の強弱の表）を付ける。JTBD と需要の5要素で課題を記録し、課題を金額や時間に換算する。 |
| 3. 集客経路と購入のきっかけの調査 | Where | 検索キーワード・検索意図・競合ページ・広告出稿・検索結果の構造、競合の流通経路を調べる。購入のきっかけになる出来事（採用・新事業・拠点開設・外注募集・システム更新）を検出する。経路は5つの軸（到達可能性・購入意図・獲得コスト・再現性・拡張性）で採点する。 |
| 4. 競合・差別化の分析 | Why | 競合の料金、高評価と低評価のレビュー、解約理由、比較記事、導入事例を調べる。乗り換えの式を評価し、差別化7種から選ぶ。「選ばれる理由」を1文で書き、根拠の証拠をつなげる。 |
| 5. 採点・ランキングと経済性の試算 | Ranking＋How | 6項目の加重スコア・足切り・事業魅力度、ファネルの段階（1000→100→20→5→1〜2）。CAC・LTV（継続期間を複数仮定する感度分析）と回収期間の試算。各数値に「証拠の信頼度」を併記し、根拠のない点数を出さない。 |
| 6. 市場実験と学習 | Experiment＋Learning | LP＋広告・個別営業・無料ツール・先行案内・限定販売の実験を設計する（事前に合格条件と中止条件を決める）。実測のファネル8段階を記録し、どこで止まっているかを特定する。結果を次の採点に戻す（例: 実測の成約率と、事前の証拠や点数との関係を残し、次の候補の評価に使う）。合格したものは「プロジェクトにする」へ進める。 |

7段階の検証順（G1 顧客が存在するか → G2 強い課題があるか → G3 接触できるか → G4 購入するか → G5 利益が残るか → G6 自動化できるか → G7 拡大できるか）との対応:
機能1 → G1（実験で G3）、機能2 → G2（実験で G4）、機能3 → G3（実験で G5）、機能4 → 「プロジェクトにする」の条件（実験で G4）、機能5 → 比べる順と G5 の見積り、機能6 → G4〜G7。
流れは Discovery（機能1〜3）→ Evidence（機能2・4）→ Ranking（機能5）→ Experiment（機能6）→ Learning（機能6の結果を機能5の採点へ戻す）。

# 第2部 調査の具体的な方法と評価（ユーザー提供ナレッジ 2026-10-18・その2）

第1部（集客の5原則・6機能）と矛盾するところは、この第2部を優先する。対応: 評価の主軸は「成立条件ごとの支持・反証・未確認・次の確認」（6項目の加重スコアは補助）、調査の単位は「購買が起きる場面」、証拠は11項目と読む5観点、収集と評価は別の工程・別の依頼、次の行動は4つ、調査の終了条件、事業を進める段階5つと実行条件4点（プロジェクトにした後も引き継ぐ）。

「集客から組み立てる」＝「採算の合う顧客を、繰り返し獲得できる道筋から組み立てる」。無料利用者を集める構想では、集まることと収益になることのつながりが特に重要。

## 1. 集客を考える5原則（事業選び向けの整理）
1. 顧客が「すでに解決しようとしていること」から始める。困っている発言に加え、解決のためにお金・時間・人員を使っている事実（外注している／担当者が何時間もかけて調べ転記している／その仕事の人を採用している／既存サービスに払っている／今の方法では間に合わず別の方法を探している）。そこから「何を達成したくてその負担を受け入れているか」を掘る（JTBD）。例: 営業リストが欲しいのか、「今週誰に営業すべきか決めたい」のか。
2. 顧客を「状況」と「買うきっかけ」まで絞る。例:「官公庁との取引実績がある小規模IT企業で、営業責任者が案件探しと参加条件の確認を兼務。次の受注を増やしたいが調べる時間が足りない」。どの企業が該当／誰が担当／何が起きると変える必要が生まれるか／そのときどこで解決策を探すか。きっかけ: 契約更新、担当者の退職、新規案件の受注、事業拡大、締切の接近。課題の大きさと「今、動く理由」はセット。
3. 顧客が今の方法を変える理由を具体的に示す。機能→成果に変換（AI企業情報収集→今週営業すべき企業と理由が分かる／入札自動収集→検討すべき案件候補と確認すべき条件が届く／業務自動化→毎回の作業が減り期限内に処理／低価格→品質を確かめながら支出を減らせる）。導入負担（設定が難しい、データ移行、出力確認の手間、社内説明）も見る。初期集客では相手の業務に当てはめた実物サンプルを見せるのが有力。
4. 顧客へ到達する方法も商品と一緒に決める。
   | 顧客の状態 | 最初に検証しやすい接点 | 見せるもの |
   |---|---|---|
   | 解決策を検索している | 検索広告、課題別の記事、比較ページ | 疑問への答えと具体的な成果 |
   | 対象企業を実名で特定できる | 対象を絞った営業、既存のつながり | その企業に関係するサンプル |
   | 専門家や取引先に相談している | 紹介、提携 | 紹介者が説明しやすい対象と価値 |
   | 説明や実演を見て判断したい | 動画、セミナー、製品デモ | 自分の業務でどう役立つか |
   初期は公開情報から対象企業を絞り、個社に関係する成果物を見せる（誰に届き何に反応したか把握しやすい）。反応した課題・説明を検索記事や動画に展開すると発信に根拠ができる。
5. 集める相手とお金を払う相手をつなげる。無料機能を使う→業務上の必要が具体化→発注できる担当者につながる→条件を相談→有料取引。無料ツールの利用者と有料の発注者が同じ顧客の一連の仕事の中でつながっているかを確認。「人を集めれば後で何か売れる」が残っていれば、そこが優先して試す仮説。

## 2. ネット調査でどこまで絞れるか
公開情報で候補の除外と、試すべき顧客・提案の具体化まで進められる。自社提案への反応は当人に提示して確かめる。
| 判断したいこと | ネットで探す証拠 | その証拠だけでは分からないこと |
|---|---|---|
| 課題が存在するか | 求人の仕事内容、業務手順、顧客の投稿、導入事例 | 現在どれほど優先されているか |
| 解決に支出しているか | 契約・発注情報、有料サービスの利用事例、外注募集 | 自社の提案に予算を移すか |
| どんな顧客か | 企業の実績、組織、採用情報、事例の担当者 | 誰が最終判断し誰が反対するか |
| どこで接点を持てるか | 検索語、比較サイト、業界団体、競合の広告 | 自社の訴求で反応するか、獲得費用 |
| 既存手段に何が足りないか | レビュー、FAQ、移行事例、不満 | 不足を解消すれば乗り換えるか |
| 継続して利益が出るか | 公開価格、標準的な業務内容 | 継続率、例外対応、サポート工数、実際の粗利 |
取り違えを避ける: 検索数は購入者数ではない（キーワードプランナーの「競合度」は広告主の競合）。競合の価格表や広告は採算の証明ではない。大きな開発費や発注金額は自社への支払意思と別（官公庁が数億円発注していても、応札企業が入札情報ツールにいくら払うかは別の問い）。証拠は「何が確認できたか」を狭く正確に読む。

## 3. 既存構想（入札通知）のたたき台（検証案。需要確認済みではない）
最初の顧客: 官公庁向けの実績がある小規模IT企業の営業責任者 / 困っていること: 案件探しと参加条件の確認に時間、検討対象を選びきれない / 顧客候補の探し方: 過去の落札結果、企業サイトの受注実績、公共向け事業の記載 / 最初に見せるもの: その企業が検討できそうな案件候補と適合理由・要確認事項 / 確かめる行動: 自社条件を登録、案件を検討対象にする、繰り返し利用 / 無料提供後の収益仮説: 案件を進める過程で不足するIT・AI人材や外注体制の相談 / 別途検証: その相談が実際に発生するか、発注権限のある相手につながるか、取引条件が成立するか。
確かめる需要は二つ（案件を見つけ検討する負担を減らしたい／案件を実行する人材・体制を確保したい）。同じ企業の中でつながれば無料提供に収益上の理由ができる。指標は登録数に加え、実際の案件検討、体制相談、具体的な要件共有、成約、対応工数。初期の個別対応から共通して必要だった情報・説明を抽出し標準化できるかも見る。

## 4. AIを使ったリサーチの進め方
- AIにはアイデアの大量生成より、仮説ごとに証拠と反証を整理させる。
- 調べる単位を「顧客と状況」にする（例:「新しく特定業界へ営業を始めた企業の担当者は、対象企業と担当部署を見つけるために、何を使い、どこに時間やお金をかけているか」）。
- 証拠と推測を別々に記録: 出典URLと情報の日付／誰が、どんな状況で、何をしているか／現在の対処方法と確認できる支出・工数／接点を持てる場所／推測したこと／仮説に合わない事実と未確認の点。同じ発表の転載を別々の証拠として数えない。
- 次の判断を左右する不確実性から試す: 届くか→対象を絞って接点を持つ / 価値が伝わるか→個社の成果物やデモ / 導入するほど必要か→実データや条件を登録して業務で使ってもらう / 対価を払うか→価格・範囲・条件を明示して提案 / 継続するか→次の業務サイクルでも使われるか / 利益が残るか→獲得費用・提供費用・個別対応の時間を測る。意見より購入・利用・継続の行動を強い証拠として扱う（「興味があります」は次の検証へ進む材料）。

## 5. 調査の終了条件
「対象顧客／困っている状況／現在の対処／接点／見せる成果物／収益へのつながり」が具体化し、残る問いが「この相手が実際に使うか、払うか」になったら実験へ。実験もオンラインで（個社向けページ、サンプル、オンライン商談、申込み、利用ログ）。顧客獲得・信用づくり・導入支援・無料提供の運営費も費用に含める。

## 6. 深掘り: 何をどう調べ、どう評価するか（原則から）
最終的に判断したい5点: ①その課題を今解決する必要があるか ②どの企業の誰がその状況にあるか ③現在の方法から変更する理由を提供できるか ④採算の合う方法で繰り返し接触できるか ⑤利用から支払い・継続へ進み利益が残るか。「魅力的に見えること」と「証拠が揃っていること」を別々に評価する。

### 調査単位は「購買が起きる場面」
「どんな企業の、誰が、何が起きたときに、どんな成果を必要とし、今はどう対処しているか」の一文を調査開始時に必ず書く（セグメントは到達可能・測定可能・実行可能・差異・十分な規模）。

### 原則①「解決する必要があるか」を行動と負担から
調べる項目: 発生する場面 / 頻度・期限 / 現在の作業（誰が何をどの順で）/ 詰まる場所（探す・判断する・転記する・確認する・調整する）/ 放置した影響 / 現在の対処（人を増やす・外注・ソフト購入・対象を減らす・諦める）。
検索の出発点:
| 情報源 | 検索例 | 抜き出す内容 |
|---|---|---|
| 顧客の導入事例 | "業務名" "導入事例"、"入札" "情報収集" "時間" | 導入前の作業、困った出来事、導入のきっかけ |
| 企業の求人 | "営業リスト" "作成" "求人"、"企業名" "採用" "官公庁" | 仕事の内容、担当部署、必要能力、配置人員 |
| 外注募集 | "営業リスト作成" "業務委託"、"業務名" "募集" "予算" | 成果物、量、期限、要求品質、提示予算 |
| 実務者の記事・投稿 | "業務名" "手作業"、"業務名" "毎日"、"業務名" "困る" | 実際の手順、工夫、失敗、残っている負担 |
| マニュアル・FAQ | "業務名" "手順"、"業務名" "Excel" | 現行業務の工程、自動化しにくい確認・例外 |
優先度を上げる証拠: 特定の場面で繰り返し発生 / 期限や業績への影響が具体的 / すでにお金・人員・時間を使っている / 対処しても未解決が残る / 同条件の別企業でも類似行動。下げる証拠: 現状で十分 / 発生がまれ / 改善しても結果がほぼ変わらない。
厳密な読み方: 求人→担わせたいことは分かるが外部サービスへ置き換える意思は未確認。外注募集→募集金額で契約成立したかは未確認。導入事例の工数削減→掲載顧客の経験で市場全体は未確認。
負担の金額化: 業務量 × 1件あたり作業時間 × 社内時間単価（＝負担の見積もりで支払い可能価格ではない）。入札で見逃した案件の発注総額を損失額にしない。

### 原則②「どの企業の誰が、今その状態か」
顧客候補を見つける条件（入札例）: 官公庁向け受注実績 / 公共分野の事業 / 官公庁向け営業・案件管理の募集 / 新地域・業種へ拡大 / 外部パートナー募集。調達ポータル（事業者検索・落札実績のダウンロード）、Gビズインフォ（法人番号に紐づく調達情報）。過去の受注実績は現在困っている証拠ではない→現在の事業・採用・外注・運用の情報を重ねる。
担当者を役割に分ける: 実際に使う人 / 導入を進める人 / 予算・発注を決める人 / 導入条件を確認する人。推定した役職と確認できた決裁権限は別々に記録。
今動く理由: 契約更新が近い / 新しい顧客・案件を獲得 / 担当者が不足 / 事業・拠点の拡大 / 漏れや遅れが起きた / 現行サービスの条件が変わった。
母集団の注意: 不満投稿や導入事例だけから集めると偏る。課題発見の調査（詳しく読んで仮説）と、広さを確かめる調査（業種・事業・規模などの条件で作った企業群）を分ける。割合を推定するなら対象の選び方と分母を揃える。

### 原則③「今の方法から変える理由」
選択肢: 自分で作業 / Excelや社内システム / 公的な情報・機能 / 外注 / 有料サービス / 対象業務を減らす・実施しない。
比較項目: 得られる成果 / 品質（抜け・誤り・古さ・確認の手間）/ 顧客の総負担（料金＋設定・確認・運用）/ 導入のしやすさ / 変更しにくい理由（連携、データ、契約、習慣、社内承認）/ 選ばれている理由。
検索例: "サービス名" "導入した理由"、"サービス名" "乗り換え"、"サービス名" "解約"、"業務名" "自動化" "失敗"、"業務名" "Excel" "運用"。不採用・移行・失敗の理由も探す。
入札通知の例: 調達ポータルに通知機能がある→今の方法で必要な発注元をカバーできているか、通知が多すぎないか、自社の実績・資格・人員に合うかの判断負担、締切や変更の把握、案件を見つけても検討が進まない理由。「通知機能がある」だけでは追加価値は確定しない。判断作業が重い証拠が揃えば、同じ企業条件で現行方法と自社出力を比較する実験へ。

### 原則④「どこで、どんな言葉なら届くか」
A. 顧客を特定して接触: 対象にした理由（どの公開事実が一致）/ 関係する担当者 / 接点（既存のつながり、紹介者、公開窓口）/ 接触する理由（今伝える意味がある出来事）/ 最初に見せるもの / 求める次の行動（条件登録、サンプル確認、課題共有）。一度だけ使える人脈か、同条件の別企業に繰り返せる経路かを区別。
B. 検索から来る: 意図別に（営業リスト 作り方＝学びたい / 企業 部署名 調べ方＝作業を進めたい / 営業リスト 代行 料金＝外部依頼の比較 / サービス名 代替＝変更したい / 営業リスト 無料＝費用をかけず利用、無料後の収益とつながるか）。意図は仮説、検索結果の中身も確認。調査表: 検索語／想定意図／地域・期間／推定検索量／入札単価の参考値／検索結果の内容／用意するページ／求める行動。データを取っていなければ数値欄は未確認のまま。
C. 競合の広告と申込みまでの流れ: Google 広告透明性センター。誰のどの課題に呼びかけ、何を成果として約束し、最初の行動を何にし、申込み前に事例・サンプル・価格・実績をどう見せ、どこで不安や導入負担を解消しているか。広告が続いていても黒字とは確定できない。

### 原則⑤「利用が収益につながるか」
三つの仮説: 無料の情報サービスを使いたい（条件を登録し業務で使い続ける）/ 人材・外注を発注したい（実案件、必要能力、予算、開始時期、外部発注の行動）/ 無料利用から発注へつながる（利用企業の中に発注者が存在し、適切な時点で相談・取引へ）。
買い手・売り手・両方を分ける（人材会社や受託会社は売りたい側かもしれない）。検索例: "企業名" "パートナー募集"、"企業名" "協力会社"、"企業名" "業務委託" "募集"、"企業名" "プロジェクト" "体制"、"企業名" "採用" "案件"（パートナー募集があっても現在の発注や予算は未確認）。
発注場面を分ける: 入札準備時（提案・実行体制のため外部の専門家・パートナーを探す）/ 受注後（確定案件の実行のため人員・外注先を探す）。どちらに接点を作れるかで集める企業と無料機能の設計が絞れる。
採算は同じ期間に獲得した企業群で見る（説明用の仮定）: 評価期間12か月、有料取引1社の限界利益30万円、無料利用企業1社の獲得・提供・成約前対応費6,000円 → 有料化率0.5%: 期待1,500円（−4,500円）/ 2%: 6,000円（0円＝固定費前の損益分岐）/ 5%: 15,000円（＋9,000円）。無料登録者数だけでは採算を判断できない。確かめるのは有料化率、取引の利益、成約しない利用者も含めた費用。

### 7. 公開資料の読み方の実例
NJSS 掲載の NTTデータ経営研究所の導入事例（2014年公開・2023年更新の過去事例＝現在の証拠としては扱わない。販売者掲載の顧客インタビューで独立した効果測定ではない）: 元の方法＝官公庁サイトを人が確認 / 負担＝収集に1時間以上かかる場合があり取りこぼしを懸念 / 認知経路＝社内リサーチャーの紹介 / 選定行動＝トライアルで収集範囲・情報量を評価して切替。→作れる仮説: 取りこぼさないことが重要な選定理由、実物の比較が導入判断に役立つ可能性。分からないこと: 現在の小規模IT企業にも同じ需要か、いくら払うか、自社製品へ切り替えるか、無料利用後に人材・外注を発注するか。「1時間以上かかる場合がある」から年間削減額は計算できない。

### 8. 評価方法: 成立条件ごとに「支持・反証・未確認」を記録（最初は合計点より推奨）
| 成立に必要な条件 | 支持する証拠 | 反証・別の説明 | 未確認 | 次の確認 |
|---|---|---|---|---|
| 課題が十分に強い | 具体的な負担と対処行動 | 現状で十分という事例 | 現在の優先順位 | 直近の業務を確認 |
| 対象と購入場面が明確 | 実名企業と発生イベント | 担当者と発注者が違う | 予算・権限 | 購入過程を確認 |
| 変更する理由がある | 既存手段で満たせない条件 | 既存手段で対応できる | 自社の品質・導入負担 | 同条件のサンプル比較 |
| 顧客へ到達できる | 具体的な接点と対象者 | 接点が限られ再現できない | 反応率・獲得費用 | 対象を絞った接触 |
| 収益が成立する | 実際の取引と費用 | 無料利用者と買い手がずれる | 転換・継続・対応工数 | 収益商品を提示 |
重要な条件への反証がほかの高得点で埋もれるのを防ぐ。個別対応が毎回必要なら「時間・場所に依存しにくい事業」との適合性を確認。
証拠を読む5点: 対象との一致 / 行動の具体性（感想・募集・利用・契約・支払い）/ 時点の適切さ（出来事の日と掲載日を分ける）/ 独立性（転載を別証拠として数えない）/ 選ばれ方の偏り（成功事例だけ・不満投稿だけ・特定販売者の顧客だけ）。「未確認」は需要がないことを意味しない。
AIに持たせる記録項目（証拠1件ごと）: 企業・対象者／課題／発生した出来事／観測された行動／金額・時間・頻度／出典URL／出来事の日付・掲載日／情報の発信者／そこからの推測／反証／未確認事項。収集と評価は別の工程にする（AIが見つけた情報をそのまま自説の根拠にしない）。

### 9. 次の行動の決め方
| 判断 | 条件 |
|---|---|
| 調査を続ける | 次の判断を左右する事実が公開情報から確認できそう |
| 小さく実験する | 対象・課題・提案は具体化したが、反応や支払いが未確認 |
| 保留・除外する | 必須条件への反証があり、現実的な変更でも解消できない |
| 投資を増やす候補にする | 実顧客で獲得・利用・取引・利益の再現が確認できた |
顧客への確認の質問（将来の感想より直近の行動）: 最近その作業をしたのはいつか / 何が起きて必要になったか / 誰がどの方法で処理したか / どこに時間や費用がかかったか / 他の方法も検討したか / 最後は誰がどの条件で決めたか / 実物サンプルを実際の仕事で使うなら何が足りないか。「便利そうですか」「月額いくらなら」だけでは不確実性が残る。判定基準はその事業に必要な採算から決める（一律の登録率や調査件数で合否を決めない）。
推奨順: ①有料取引が実際に発生している企業と発注場面（買い手・必要能力・予算・時期・既存の調達方法）→ ②その企業が発注の前後に行う仕事（無料ツールが役立つ接点）→ ③その接点で残る負担と届く経路 → ④無料利用と有料取引の両方を実際の行動で確認。追加調査で判断が変わる可能性とその費用を比べ、残る問いが顧客の行動でしか答えられなくなったら実物を見せる段階へ（＝調査の終了条件）。

## 10. これで事業を完全に進められるか
動かし始めるには十分。ただし上は「需要と集客を調べ、何を試すか決める手順」。事業の成立には「顧客が求めるか」「実際に提供できるか」「採算が合うか」の三つ。未確定の実行条件:
| 具体化すること | 決める内容 | 確認できたと言える状態 |
|---|---|---|
| ① 最初の有料取引 | 誰が何をどの条件で発注し、自社は何の対価をいつ受け取るか | 判断できる提案・価格・提供範囲・契約条件がある |
| ② 提供する能力と供給 | 必要な品質・時期・費用で誰が何を提供するか | 実際の条件で提供できることを確認 |
| ③ 最初の実験 | 対象、見せるもの、担当、使える費用と時間、観測する行動 | 結果に応じて継続・修正・停止を判断できる |
| ④ 利益と運用 | 獲得から提供・請求・入金・問い合わせまで誰が担いいくらかかるか | 代表の作業も費用に含め、利益と入金までの資金負担を把握 |
特に②（供給）が抜けやすい: 買い手に具体的な発注案件があり、その条件で対応できる供給側がいること。自社がどの契約形態で関与し何を引き受けるか（許認可・契約準備は未確認）。
段階ごとの「進んだ」の判定: 需要の検証（課題を持ち解決のために行動する）→ 初回取引の検証（具体的条件で契約し、価値を提供し対価を受け取る）→ 再現性の検証（別の同種顧客でも成立）→ 採算の検証（成約しなかった顧客への費用も含め利益が残る）→ 運営の検証（あなた以外でも必要な品質で繰り返せる）。最初の1件は取引が成立する証拠、安定収益の証拠は繰り返しから。代表が毎回営業・調整・品質確認を抱えるなら、引き継いだ後にも利益が残るかを確認する。
