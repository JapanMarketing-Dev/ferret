## 1. UI/UX の決まり

### 配置・密度
- ★段組は「本文＋右の欄」の2列で全画面共通にする。3列にしない。
  「3レイアウトはやめてください。2レイアウト全体で共通。」〔10-13 #83・#66 NG〕
- 画面ごとに見た目や配置を変えない。見出し・パンくず・右の欄の幅は共通部品とトークンで決める。
  「今ってなんかページごとにレイアウトが微妙に違ったりしているので」「共通レイアウトを私は期待してます」〔10-13 #54・#56・#85・#87〕
- ★共通の形を崩してまで「おしゃれ」にしない。新しくするのは頼まれた点だけ。
  「やはり他のフッターと違いすぎるので。前のフッターのままコンセプトを出すだけにしてください。」〔10-12 #204、2回 NG〕
- 細かく区切った枠やカードにしない。1つの大きな面にまとめ、間は罫線1本で分ける。
  「セクション分けないでいいですもう…1ページに」「セクションで分けてるのでこういうのをやめてください」〔10-13 #98・#11〕
- 余白を余らせず、画面の幅を全部使う。
  「余白が余ってるので…全体を使ってください」〔10-13 21:07 #25〕
- 右の欄は、そのページの中を移動する目次にする（押してもページは移らない）。見出しは「ページ内容」。
  「右はもう このページ内の 目次にしてください全部」「ページ遷移するんじゃなくて」〔10-13 #33・#34・#7〕
- 右の欄は畳んで1列にできるようにする（全ページ共通）。畳むボタンは欄の中に置き、ヘッダーには置かない。
  「サイドバーなしの1レイアウトにも できるように」「これはヘッダーに付けないこと」〔10-13 #27・#28〕
- 右の欄を画面に固定しない。ページと一緒に流れるようにする。
  「サイドバーは固定しないこと。」〔10-12 #191〜#200 で同じ指摘が6回〕
- 絞り込みや検索の条件は右の欄にまとめる。本文には検索欄と結果だけを置く。
  「やっぱ全部サイドバーに移行してください」〔10-13 20:57 #3〜#6・#10〕
- 大きな区分（ナビ）は5つ程度に絞る。招待・ログアウトなどの細かい操作は設定やメニューに入れる。
  「でもこっちが大カテゴリーです。なので5つとかですね。」〔10-13 #35・#40・#48〕
- 一度設定すれば済むもの（AI の設定など）は、上のナビに出さず設定に入れる。
  「これ1回設定したらもう使わないのでAIは設定の方に入れてください」〔10-13 #47〕
- ホームには「いま自分がやること」（期日順のタスク）だけを置く。ほかの画面へ行ける情報は置かない。
  「ホームは本当に今対応すべきもの」「このセクション全部削除」〔10-13 #40〜#42〕
- 普段は編集用の欄（ラベルやセレクト）を隠す。ペンのボタンを押したら編集できるようにする。
  「ずっとこの…セレクトボックスあると結構邪魔なんで…ペンのボタン」〔10-13 #27〕
- ドラッグで変えられるものに、同じ操作をするセレクトを重ねて置かない。
  「状況はこれなしでいいです これドラッグ ここにあるだけでもわかるので」〔10-13 #19〕
- 同じ働きの欄が2つあれば1つにまとめる。
  「これややこしいので一つにしてください」〔10-13 #33・#34、#83〕

### 1行に収める・揺れをなくす
- ボタン・札・見出し・ナビは2行に折り返さない。収まらない分は「…」で切り、全文はツールチップで見せる。
  「こうやって2行にしないでください ダサいので」〔10-13 #47・#48・#55、10-14 #63〕
- 例外として、カードの概要は最低2行にして中身が分かるようにする。
  「ここの概要が1行はやめてください これ最低2行にしてください」〔10-13 20:57 #2〕
- マウスを重ねたときや開いたときに行の高さを変えない。
  「マウスオーバーで高さを変える機能削除。」「高さ変えなくていいです」〔10-12 #190、10-13 #38〕
- 再読み込みのたびに位置が動く部品は固定する（ヘッダーのアカウント欄など）。
  「リロードするたびにここが更新されてかくつく。ここは固定でいいです。」〔10-12 #203〕
- 画面を切り替えるときに、前後の画面を重ねて溶かすような動きを入れない。
  「なんかこんな感じで変えないでください」〔10-13 #86〕
- 押す場所は固定する（Ferret の比較画面の OK ボタンの位置を固定。続けて押しても動かない）。〔handoff 0.6.27〕

### 読み込み中
- 読み込み中の輪はなるべく出さない。前に見た内容や覚えたログイン状態ですぐ描く。
  「毎回ロードしないで」「ローディングなしにしてほしい…とにかくここ早く出したい」〔10-12 #160、10-13 17:22 #1〕
- 読み込み中に一部だけ先に出さない。出すなら、そろってから全部を一度に出す。
  「ここだけ最初に出るのでこれはちょっとダサい…画面全体はローディングする」〔10-13 #24・#25〕
- ヘッダー・パンくず・見出しは、読み込み中でも隠さない。
  「ヘッダーが出てないですね…全部表示させるようにしてください」〔10-13 #61・#51〕
- ★ログインが必要な画面に未ログインで来たら、待たせずログイン画面へ送る。
  「ログインしていないならリダイレクトして。登録かログインページへ」〔10-13 17:22 #2 NG〕

### 空の状態・案内
- 一度終えた「はじめにやること」は二度と出さない。
  「1個やったらもうずっと出さないでください…永久的にもう表示させない」〔10-13 21:07 #8〕
- 用語の説明は本文に書かず、マウスを重ねたら出るツールチップにする。
  「マウスオーバーしたら全部これ出るようにしてください ツールチップで説明」〔10-13 #40・#72・#76・#92・#100〕
- 入力が多い所には「AI で入力」を付ける（依頼文をコピー → 自分の AI に貼る → 答えを貼って取り込む）。
  「データ入力非常に多いので…全部 ai で入力させるようにして」〔10-13 #75・#91〕
- 選ぶ候補が多い欄は、文字を入れて探せるようにする。毎回入れる値は設定の既定にする。
  「これ毎回チェック入れるの非常に面倒なので…設定で」〔10-13 #78・#95・#89〕
- アイコンや画像が取れないときも、空欄や切れた文字にしない。同じ大きさの代わりのアイコンを出す。
  「アイコン画像は全部出るようにしてください」〔10-13 #39・#42・#14〕

### エラー・失敗の見せ方
- 送れていないのに「送りました」と出さない。失敗したら失敗と正直に出す。
  「確認メール届かない」→ 原因は送信を断られていたのに成功と表示したこと〔10-12 #167〕
- 英語の生のエラーやファイルのパスを画面に出さない。短い日本語で理由を出し、作業は続けられるようにする。〔validation.md 異常系、2026-10-03〕
- 壊れた記録は「開けません」と出す。上書きはしない。〔validation.md ab-09〕
- 時刻で書くと誤解される期限は、「30分以内」のように長さで書く。
  「21時24分 なんか今の時間かと思って一瞬バグかと思う」〔10-13 20:57 #29〕
- 入力欄でのエラーは、その欄の下にすぐ出す。
  「登録できませんみたいな」〔10-13 20:57 #21・#22〕

## 2. 文言の決まり
- 説明文は消す。見出しの下の説明、注記、「次にすること」、件数の注記などは全部いらない。
  「こういう説明文系全部削除しておいてください ややこしなので」「一回使えば分かるので」〔10-13 #92・#43・#4・#13・#12、20:57 #6〕
- AI が書いたような硬い言い方をしない。普通の業務用語にする。
  「パスじゃなくて追加ね こういうところ AIっぽいのでやめてください」〔10-13 #101〕
  例：足す→追加／確かめる→確認する／外す・消す→削除／つなぐ・外す→接続・解除／やめる→キャンセル〔#77・#97・#101・#103〕
- 「原典」のような気取った言葉を使わない。
  「原点って日本AIしすぎるので これ使わないでください」〔10-13 10:15 #5〕
- くだけた語や子ども向けの語を使わない。使う人は会社員。
  「この普通とかやめてください ビジネスマンが使うので」〔10-13 #55〕
- ぼかした言い方をせず、言い切る。
  「対応できそうな人ではなくて対応できる人にしてください」「いるっていうか必要ですよね」〔10-13 #3・17:22 #13〕
- ★「（任意）」のような但し書きを付けない。
  「（任意）はなしで。」〔10-13 #84 NG〕
- 見出しは短い名詞にする。
  「自社が参加できるか」→「自社が参加」、「このページの内容」→「ページ内容」、「ログインの決まり」→「ログイン設定」、「頼めること」→「依頼事項」、「入札の準備」→「入札準備」〔10-13 #5〜#7・#104・#57・#39〕
- 一度決めた語は全画面でそろえる（通知・メール・フッターも）。文言ルールの一覧に書き足す。
  「自社に合うは他のところも全部削除して…自社にマッチする入札にしてください 統一で」〔10-13 10:15 #8、#30・#34〕
- ★AI は「手元の AI」ではなく「あなたの AI」と書く。
  「手元のAIではなくあなたのAI」〔10-12 #178 NG〕
- ★見出しは1〜2行に収める。本人が書いた文はそのまま使う。
  「4行ではなく2行か1行へ。」〔10-12 #177 NG〕
- 自分で決めた作り直しより、前の版の文言を優先する。変わってしまったら git の前のコミットに戻す。
  「前のコミット Gitを見直して前のやつにしてください」〔10-13 10:15 #3・#4・#13〕
- 取り違えやすい数字は出さない。分からない値に「不明」と付けて出さない。
  「予定価格は…落札金額と間違えるし」「不明とか出ても意味わからない」〔10-13 #30〜#33・#10・#37〕
- 中身が分かる概要を書く。ID・日付・期限・機関名など、ほかの所で見える情報を繰り返さない。
  「これが何なのかっていうところを中心に」「こういうIDとか別出さなくていい」〔10-13 17:22 #12・#19〕
- 「コピーしました」で表示を書き換えない。知らせは下に出すだけ。何がコピーされたかは「依頼文を見る」で全文を確かめられるようにする。〔10-13 #15・17:22 #56〕
- 上限など、細かい仕様を画面に書かない。
  「8文字以上…128文字など書かなくていい」〔10-12 16:14 #33〕
- 意味の分からない飾りを置かない（関係のない所に AI のアイコンを付けるなど）。
  「ここにAIがあるのは意味不明。」〔10-12 #161〕

## 3. 動作・信頼性の決まり
- OK は最終にする。Agent が後から書き換えても、完了の状態を戻さない。人が戻したときだけ再び開く。〔handoff 0.6.27〕
- 価値の確認が OK だったと推測しない。本人の実機確認を「待ち」として一覧にしておく。
  「本人の実機確認待ち（OK を推測しない）」〔handoff、CLAUDE.md 2026-10-03〕
- 判断に迷う点（上限値やローカル扱いの範囲など）は、決めた理由を書いて本人の確認を待つ一覧に載せる。〔handoff〕
- 一覧の検索条件は、画面を戻ったときに元に戻す（全ページ共通）。保存した条件も呼び出せるようにする。
  「1個前に戻った際は検索フィルターを常に戻すようにしてください これ全ページ共通で」〔10-13 17:22 #17・#18〕
- まだ保存していない状態を見せる（未保存の帯と保存時刻）。保存せずに画面を離れるときは確認する。
  「1個前のデータって保存されてるのか 今非常に不安になりました」〔10-13 #81〕
- 変えた値はほかの場所にもすぐ映す（名前を変えたらヘッダーも変える）。
  「今変えたのに上変わってないので」〔10-13 21:07 #35〕
- 「前回使った方法」のように、最後の状態を覚えて札で示す。開いていたタブも覚える。〔10-12 #166、10-13 #43〕
- 致命的な流れ（登録・ログイン・パスワード再設定）は結合テストで最後まで通す。
  「登録ログインができないパスワードリセットできないっていう致命的な問題」〔10-13 20:57 #31・#27・#28〕
- 一部の値に偏る並び（収集の都合で同じ県ばかりになる等）は、無作為にして散らす。〔10-12 #176・#185、10-13 10:15 #2〕
- 記録は本来の操作を待たせず、失敗させない。追記だけの形で残し、壊れた行が前の行を巻き込まないようにする。〔03_design 7.1〕
- 外への送信や書き込みは許可リストと上限で守る。合言葉やパスはログに出さない。〔03_design 13〕
- 発話の断片や外国語の誤認識（「Un momento」「and」など）は要望と見なさない。変えずに「仮定」と書いて残す。〔10-13 #2・#16・#24・#38〕

## 4. テスト・確認の決まり
- 価値の確認前は単体テストを中心に速く回す。遅い E2E は作らない。外に接続しない数十秒の高速 E2E（手元で配る画面・fixtures・見た目の差分・axe）は作ってよい。
  「低速なe2eが嫌です。高速e2eであれば問題ないです」〔CLAUDE.md 2026-10-10・10-14〕
- 単体・結合テストは、境界と異常系を含めて多めに入れる。〔CLAUDE.md、handoff の注意点〕
- 直したら AFTER の画像を、指摘と同じ状態で撮る（ログイン後・開いた状態・複数件が見える位置など）。写らない動きは「静止画では写らない」と書く。〔log 全体〕
- 本番に出ていない値を差し込んで撮ったときは、そのことを書く（「手元の抽出値を API に重ねた」など）。〔10-13 #10〜#12〕
- 速さは数字で示す（例：画面が出るまで約1.5秒→0.6〜1.0秒）。〔10-13 21:07 #2〕
- 開けない資料やリンク切れは、実際に全部開いて確かめる。開けない理由は理由のページで見せる。〔10-13 #26〜#29〕
- 異常系はシナリオの一覧にして実際に操作して確かめる（不正な入力、連打、保存先が消える、壊れた記録、2000字や絵文字、全削除して戻す）。〔validation.md〕
- 1280px と 390px の幅で横にはみ出さないことを確かめる。動きを減らす設定では止める。〔lp-design.md、10-12 #174・#186〕
- 確かめていない OS や機能を合格扱いにしない。〔03_design 12〕

## business-ADE に当てはめるとき
- 日本語だけのデスクトップアプリなので、2章の文言の決まりは全画面に適用する。最初に文言の一覧（統一する語）を作り、変えたら追記する。
- 段組は「本文＋右の欄（畳める・画面に固定しない）」の2列に統一する。読み込みは前の状態で即表示を基本にする。
- 確認の「OK」は人だけが出せる最終の判断として扱う。推測で完了にしない。
