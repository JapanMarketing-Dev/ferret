Ferret 0.8.5

- The built-in browser uses far less memory. Only the front tab and the two you used most recently keep their pages loaded; other tabs go to sleep (shown dimmed with 💤), keeping their title, address and back/forward history, and reload when you click them. Switching projects or starting Ferret loads only the front tab instead of all of them. You can open up to 10 tabs (was 20).
- Links that a page opens in a new tab now open in your external browser (Chrome, Safari, …) instead of piling up as built-in tabs. Links to your local development pages (localhost and the like), sign-in popups, and anything you open from the address bar, presets or an agent still open in the built-in browser.
- Ferret watches its own memory use every 30 seconds. If it reaches a quarter of your computer's memory, background tabs are put to sleep; if it is still above 35% after that, you get one short notice (not repeated for 30 minutes). Thresholds are a share of your computer's memory, so they fit any machine.
- If a page in the built-in browser crashes (for example because memory ran out), it no longer stays blank: a background tab goes to sleep and reloads when you click it, and the front tab says what happened and offers a reload.
- An agent can no longer drive the built-in browser of a project you are not looking at. Each terminal may only use the built-in browser while its own project is open in Ferret; when you are on another project, the agent is told the browser is busy with another project and nothing opens or changes there.
- Agent skills: value use cases are now treated as the definition of done, so agents break them down into finer steps, add a screenshot (or mockup) to nearly every step, and file a detailed visual review for every place the product differs from how it should be.
